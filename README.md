# PRC Data Challenge 2026 — taxi-out prediction (team lighthearted-sandwich)

A solution to the EUROCONTROL Performance Review Commission data challenge: predicting the
taxi-out time of departures (`TAXITIME_SEC_mvt`) at the ten final-round airports over January,
February, June and July 2026. This repository ships the training and prediction code, the frozen
models, the measurement protocols, the full dated decision log (including the experiments that
failed), and the inference app that regenerates the submission files.

The **full methodology report** is provided as a PDF in [`paper/RAPPORTFinalPRC26.pdf`](paper/RAPPORTFinalPRC26.pdf).
The technical appendices live in `docs/` — English first (`docs/EN/`), French originals second
(`docs/FR/`).

## What is and is not included

- **Data are not redistributed.** The challenge data (2025 training, ranking entries and templates)
  belong to the organiser and are obtained from them (Data page, MinIO client). Once downloaded,
  point `configs/paths.local.toml` at that folder (a copy of `configs/paths.example.toml`, ignored by Git).
- **Submission files are not versioned.** They are regenerated in one command (`python app/infere.py`)
  from the frozen models committed here; their SHA‑256 fingerprints (§ Fingerprints) let you confirm a
  reproduction is byte-identical to what we submitted.


## Reproduce — retrain from scratch

On macOS, install `libomp` first if LightGBM refuses to load (`brew install libomp`).

```bash
uv venv --python 3.13 .venv
uv pip install --python .venv/bin/python numpy pandas pyarrow lightgbm scikit-learn pytest
cp configs/paths.example.toml configs/paths.local.toml    # point at the read-only official data folder

pytest -q                                                 # 57 tests: contracts, leakage, metrics, template

# development folds (one held-out month among Jan/Feb/Jun/Jul 2025)
python -m src.train    --config configs/tabular_causal.toml   --run-id causal-r2   --no-fingerprint
python -m src.residual --config configs/tabular_residual.toml --run-id residual-r1 --causal-run causal-r2

# freeze the final models (iteration counts taken from the fold medians)
python -m src.train_final --config configs/tabular_causal.toml   --run-id causal-final   --from-report reports/causal-r2.json
python -m src.train_final --config configs/tabular_residual.toml --run-id residual-final --from-report reports/residual-r1.json
```

## Reproduce — infer and validate

The frozen models under `models/` are byte-identical to the `*-final/final` artifacts, so inference
needs no retraining:

```bash
python app/infere.py --famille A --equipe lighthearted-sandwich   # A = causal, B = reconstruction
python app/controle_causal.py                                     # 50,000 departures: max deviation 0.0 s
python -m src.validate_submission --file submission/<file>.parquet # ids, order, dtype (int32 target), finiteness
```

`app/infere.py` runs the compliance check before writing anything; a single failed control aborts with a
non-zero exit code. `controle_causal.py` rebuilds inputs and predictions twice — once as distributed, once
with realised take-off time, realised off-block time and the runway actually used blanked out — and requires
an identical input matrix and zero change in predictions.

## Reproduce — audits and projections (read-only)

```bash
python -m src.audit                # two off-block sources cross-check (the implausible-rows pocket)
python -m src.score_projection     # difficulty distribution of the 2026 population + 2025->2026 drift
PYTHONPATH=. .venv/bin/python scripts/null_rates.py   # per-column absence rates, 2025 and 2026
```

## Two tracks, named and acknowledged

The official rules fix **no prediction instant** and forbid **no column**; the absence of a prohibition is
not an authorisation. We therefore keep two explicitly separated recipes rather than silently mixing the two
kinds of information:

- **Prediction (causal)** — only what is known before pushback (schedule, airport, aircraft, stand, operator,
  *planned* congestion). This is the default solution and fallback; local RMSE 557.1 s over the four target months.
- **Reconstruction (residual)** — adds realised take-off time and the M3 realised off-block; the target is
  written as *proxy + correction*. Stronger locally (479.9 s) but it reads information produced after departure,
  so a ranking obtained with it would not carry the same meaning. **We ranked the causal prediction**; the
  reconstruction track is documented for transparency and reproducible with `--famille B`, but was deliberately
  not submitted — an admissibility decision recorded in `docs/EN/DECISIONS.md` (D‑004).

Details in `docs/EN/T0_DISPONIBILITE.md`, `docs/EN/FEATURE_ADMISSIBILITY.md`, and the report PDF.

## Licence and tooling

All code in this repository is released under the GNU GPLv3 (`LICENSE`). The organiser's data files are not
redistributed here.

We worked with agent-based AI running locally on our own hardware (OpenCode as the agentic harness, Arbor for
hypothesis-tree orchestration, open-weight language models served locally). The team chose the rules, read the
measurements and made every decision; the tooling executed and audited. No leaderboard feedback was used to tune
the recipe: each methodological decision was settled on 2025 data before any deposit (`docs/EN/CLEAN_ROOM.md`).

## Known limitations

- Rome Fiumicino (LIRF) is not explained: on its *normal* rows the crude proxy still beat our absolute model.
- The dominant error pocket — departures with no network flight list — has no second measurement to corroborate
  it; three specialisation attempts were rejected for lack of gain. This bounds what any recipe can reach (D‑028).
- Our local-to-ranking transfer factor (+5 to +7 %) was measured on arrivals, not departures; it covers the level
  shift only, not the uncertainty on extremes (D‑036).
